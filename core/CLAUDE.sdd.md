# SDD (Spec-Driven Development)
Applies in repos that contain `specs/constitution.md`, or when the user invokes `/sdd-*` or the `sdd-orchestrator` agent. Elsewhere, ignore this section.
- Coordinator: agent `sdd-orchestrator` (`/sdd-init` sets it as the default agent via `.claude/settings.local.json`; otherwise `claude --agent sdd-orchestrator`). Phase skills: `/sdd-init` `/sdd-spec` `/sdd-clarify` `/sdd-plan` `/sdd-tasks` `/sdd-implement` `/sdd-validate` `/sdd-review` `/sdd-memory` `/sdd-status` `/sdd-release`.
- Artifacts live in `specs/<feature>/{spec,plan,tasks,acceptance}.md`, ADRs in `specs/adr/`, project memory in `memory.md` at the repo root. This overrides Superpowers' default `docs/superpowers/{specs,plans}/` paths; `/sdd-release` replaces `superpowers:finishing-a-development-branch`.
- Caveman applies to chat only: specs, memory.md, ADRs, commit messages, security warnings and test results stay in full prose. Ponytail never removes validation, error handling, security, accessibility or needed tests.
- Done means: acceptance criteria verified with commands run in this session, review approved, memory.md current. Compiling is not done.
- Git: once the `/sdd-release` quality gate passes, the local commit is automatic. Push is automatic only when this clone has `git config sdd.autoPush true` (set by the user via `/sdd-init`, never by you on your own) and the constitution does not forbid it, and only to a working branch, never to the default branch. Never force-push, rewrite shared history, push to protected branches or an unexpected remote, deploy to production, or run destructive migrations without specific authorization. Never `git add .` when unrelated changes exist.
